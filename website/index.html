01 / THE APPROACH

A verdict should come
with context.

A familiar command can hide a different effect. An unfamiliar command needs an honest answer. Distill keeps three questions separate.

01

What could it change?

Model supported command behavior: file operations, nested execution, network transfers, and other effects.

IMPACT
02

What can we account for?

Keep unsupported syntax, dependencies, and missing shell context visible. A known impact can still have incomplete coverage.

COVERAGE
03

What should happen next?

Apply configurable effect policy to allow, request review, or deny. Host permissions remain a separate boundary.

03 / CLEAR BOUNDARIES

Local by design.
Explicit about limits.

Read coverage and limits →
◎

No cloud analysis

No model or network service runs in the analysis path. The analyzer works on your machine.

◒

Unknown means unknown

Static analysis is bounded. Recognizing a tool does not prove arbitrary application code safe.

⌁

Privacy has boundaries, too

Editor history is memory-only. The separate session ledger persists bounded hashes and policy state.

⊞

Containment is opt-in

analyze does not execute commands. run uses native containment; installing hooks does not enable it automatically.

One extension. CLI included.

  1. Follow the extension install guide to build a platform-specific VSIX from source.

  3. Review the generated hooks in your agent, then open the Distill sidebar.
Extension install guide ↗

Marketplace and prebuilt release packages are not published yet. Building a VSIX requires Rust, Node.js, and Python; the installed extension includes the CLI.

BUILD FROM SOURCE

A small CLI. A closer look.

git clone https://github.com/HarshD0011/distill.git
cd distill
cargo install --path crates/distill-cli --force
distill analyze --command 'echo hello' --human

Requires a Rust toolchain supporting edition 2024. Run from the cloned repository.

Connect your agent.

# Preview before changing user hook definitions

Run from your workspace root and review the definitions in Codex’s /hooks. For Claude Code, use distill setup claude. Manual setup uses strict defaults; existing host permissions still apply.

A FEW USEFUL ANSWERS

Before you begin.

Does Distill execute the command to analyze it?+

No. analyze and hook assessment inspect commands without executing them. The separate run subcommand is an opt-in execution gate.

Is a “safe” rating a guarantee?+

No. It describes modeled impact within the supported static semantics. Coverage, source dependencies, shell context, and host permissions still matter. Incomplete coverage can require review even when the modeled impact is safe.

Does installing the hooks sandbox my agent?+

No. Hooks are analysis adapters. Execution goes through native containment only when explicitly routed through distill run. macOS uses Seatbelt; supported Linux kernels use Landlock and seccomp.

Which editor environments are supported?+

The extension supports trusted local desktop VS Code folders on macOS and Linux, on arm64 and x64. Windows, remote workspaces, WSL, containers, and browser VS Code are not currently supported by the extension.
